# 全天任务闭环

## 目标

把客户邮件、上级安排和跨部门协同整理成一批具有稳定身份的任务。早间清单、白天更新、晚间提醒必须引用同一任务 ID，不能在每次汇总时重新生成一批相似任务。

## 任务建立

1. 保留原始来源引用、来源类型、原文时间和可回看的定位信息。
2. 提取任务名称、负责人、客户或事项、截止时间、下一步动作和完成条件。
3. 同一事件的重复消息合并到已有任务，并追加来源，不重复建任务。
4. 没有明确期限、负责人或完成条件时标记为“待确认”，不得自行猜测。
5. 早间清单只展示当前用户可见且仍需处理的任务；管理汇总遵守团队数据权限。

## 状态判定

- 待确认：缺少期限、负责人、事实或明确动作。
- 待处理：任务信息完整但尚无执行证据。
- 处理中：存在已开始的真实记录，但完成条件尚未满足。
- 待审核：产物已生成，但仍需人工审核、批准或发送。
- 已完成：完成条件已满足，并且存在可回读的完成依据。
- 受阻：缺少价格、权限、资料或外部系统可用性；必须写明缺失条件和下一步。

阅读消息、打开页面、生成草稿都不能自动代表任务已完成。例如，已生成报价草稿但尚未审核发送，只能是“待审核”。

## 全天闭环

1. 早间：生成今日任务快照，保存任务 ID 和当时状态。
2. 白天：人工或系统更新同一任务，记录状态变化人、时间、依据和备注。
3. 晚间：回读早间任务集合，逐项核验完成依据；不得用新建任务代替早间任务。
4. 对未完成任务输出当前状态、缺失条件和下一步行动。

## 完成标准

- 能从每个任务回到原始信息来源。
- 个人端和管理端读取同一任务与状态记录。
- 晚间汇总中的任务 ID 与早间清单一致。
- 所有“已完成”状态均有可回读的完成依据。
