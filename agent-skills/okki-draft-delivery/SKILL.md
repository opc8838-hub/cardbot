# 小满草稿交付与复核

## 目标

把已经通过人工审核的 CardBot 本地草稿保存到小满草稿箱，并以小满中的可回读结果作为完成证据。统一连接器支持 Mock、官方 API 和 Playwright RPA，业务层不得依赖其中一种实现细节。

## 模式选择

1. 官方 API 已开通且公开草稿能力时优先 API。
2. 没有草稿 API但允许网页自动化时使用 Playwright RPA。
3. 没有真实账号或开发测试时使用 Mock；Mock 结果必须醒目标注，不得作为比赛验收证据。
4. 模式由连接器配置决定，草稿业务流程不因模式变化而改写。

## 保存流程

1. 只接收“人工审核通过”的本地草稿版本。
2. 锁定收件人、主题、正文和本地草稿版本，生成幂等键，避免重试产生重复草稿。
3. 调用当前模式保存，记录连接器模式、请求时间、外部草稿定位和真实错误。
4. 保存后重新查询草稿，核对收件人、主题和正文摘要。
5. 真实账号验收时退出并重新登录，再查询同一草稿，记录复核时间和证据。

## 失败恢复

- 登录失效：停止当前保存，标记需要重新登录；不得反复尝试验证码。
- 页面结构变化：保留本地草稿和诊断截图，标记 RPA 选择器失败。
- API 权限不足：展示真实状态码和缺失权限，不自动转为成功。
- 保存结果不确定：先查询草稿箱；无法确认时保持“结果待确认”，不得盲目重试。

## 完成标准

- Mock：仅证明接口契约和业务流程可运行。
- API/RPA：小满草稿箱能查询到内容一致的草稿。
- 最终比赛验收：重新登录后仍能找到同一草稿，且全程没有自动发送邮件。
