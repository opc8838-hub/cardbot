# 继续开发路线与决策记录

## 已确认的用户意图

- 名称统一 CardBot；界面与项目原创代码不出现旧品牌。第三方合法许可与署名不得伪造。
- 两个赛题合成小工作台/SaaS 皆可，先完成最短闭环，不先扩大模块。
- 模型选择 DeepSeek，暂不配置真实服务；不要提前消耗模型预算。
- 先历史邮件与现有客户，再新客户获客；一键全服务安装/启动可以晚些做。
- 问候要有停留，功能页没有登录表单；登录独立以后设计。
- CARD 背景用小词构形，五个大词不变；地球也由小词组成；黑白可切换。
- 源码、计划、缺口、验证和交接同步 Git，让新电脑/新账号可接手。
- 企业 Demo 先采用“一套企业连接 + 每位业务员独立 user_id 映射”；经理看团队，业务员看本人数据。
- 用户确认先演练“假设已接入 API 后的工作体验”；2026-09-12 已完成左侧导航工作台和七步播放器，保留品牌入口与地球。此阶段不等待企业 API。
- CardBot 同时是品牌角色和知识助手入口：扑克牌 Bot 可按账号选表情/颜色；当前只演示对话壳与预置回答，正式知识库问答留到权限和数据来源明确之后。

## 为什么现在这样拆

1. **新入口与 CRM 隔离**：避免为无登录预览开放真实客户数据。代价是当前预览与后端尚未绑定，必须公开标注。后续通过 Repository/API adapter 接真实数据，不能复制另一套后端。
2. **功能页不自动跳走**：Hello 有约 6.7 秒节奏；大字页由用户点进入。工作台功能切换直接呈现业务内容。
3. **Canvas 字体地形**：复用地理数据绘制原创文字球，满足“文字组成”而不是贴截图。继续优化可做倾角、按客户聚合热点和真正的城市定位，但必须标明数据来源。
4. **本地审核优先**：在真实账号未准备前，可以验证状态、事实边界、失败不丢稿；不能据此声称赛题最终完成。
5. **不大量堆开源框架**：采用现有 Vite/Express/PostalMime/地理组件，先让各段可验证；IMAP 或 RPA 确有需求再加入。

## 下一阶段顺序（每阶段有退出标准）

### P0 — 本次视觉与企业身份 Demo

已完成左侧导航工作台、七步业务演练，以及 logo 旁的个人扑克牌 Bot 选择与知识助手对话演示。演练时间与真实上海时钟分开；保留原手动数据。下一步先请企业试播并反馈实际流程，再推进 P1 后端绑定。不要把模拟审核/保存回执或 Bot 预置回答当作真实员工操作、小满保存证据或模型检索结果。

退出标准：用户认可当前首屏与操作预览方向；桌面/手机、黑白、键盘、低动态仍通过。

### P1 — 新 UI 绑定现有核心 API

- 定义 WorkdayRepository、EvidenceRepository、DraftRepository 的统一类型，隔离 preview/local/API 实现。
- 先接只读任务及来源，再接状态更新与早晚聚合；复用真实身份与团队权限。
- 草稿编辑应绑定修订版本和审核版本，不只靠按钮 disabled。
- 审计 `/deliver`：审核状态必须在任何外部调用前检查；Mock 不能伪装真实 receipt；保存邮件不能把“已发送报价”任务判完成。
- 补 HTTP 级未审核外写零调用、越权、并发编辑、重复保存、失败保留内容测试。

退出标准：同一测试账号，API 与新 UI 看到同一任务/草稿；刷新和权限边界通过；纯 Mock 与真实模式明确分开。

### P2 — 历史邮件与 DeepSeek

- 获授权 EML 批量导入；如果需要邮箱在线读取再接 ImapFlow。
- 邮件线程、引用出处、缺失事实、冲突约定、附件产品信息与版本字段。
- 配置 DeepSeek 服务端适配与结构化输出，记录实际成本和失败，不让模型判断“已经发送”。
- 做 10—20 组脱敏代表样例，至少含询价/交期/客诉与不完整历史。

退出标准：模型草稿每个关键业务事实能回源，缺失事项明确，风险承诺需人工审核，错误可复现。

### P3 — 真实小满

- 先获得主办方回答和测试授权；官方 API 优先，不足时 RPA。
- 独立后台 Worker，不把浏览器长任务放在 Web 请求里等待。
- 保存前验证状态/客户/收件人/内容；保存后读回；重复请求幂等；超时不确定先查再重试。
- 草稿箱人工复核并重新登录再查。收集不含凭证的验收证据。

退出标准：一个真实草稿可在小满查到且重登录后完整存在；未审核不能写；保存失败本地稿可恢复。

### P4 — 新客户获客整合

将原线索发现/来源/客户背景能力接到事实与草稿管线。缺邮箱转人工，不编造联系资料；公开网站不等于任意采集授权。新增开发信不应绕开审核/小满保存验证。

退出标准：一条授权来源线索能解释为什么适配产品，并形成有依据的小满草稿。

### P5 — 交付与生产化

跨设备数据库、租户权限、密钥轮换、审计、监控、限流、备份恢复、部署与一键安装、完整 CI、多浏览器性能检查。登录页按用户后续设计另做。正式 SaaS 上线前单独做安全评估。

## 亮点：如何向评委解释

- 工作与销售不是两个孤立聊天框：同一任务连接信息、事实、草稿、人工判断和下班提醒。
- “有据可依”优先于“文笔漂亮”：证据可追溯、未确认项不隐藏。
- 机器负责准备，人负责承诺：审核是状态约束，不是装饰按钮。
- 失败也有完整路径：保留草稿并说明下一步，不以动画/成功提示冒充完成。
- 全球贸易语境：多语言入口、文字地球、跨时区参考；目前是体验与信息表达亮点，不夸大为全球实时业务地图。

这些是设计目标和当前实现方向；最终参赛展示必须用 STATUS 与真实测试证据限定主张。
