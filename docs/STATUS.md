## 接入层的真实能力

- Mock：能产生模拟保存回执，不能登录小满查到，不具有远端保存证明力。
- 官方 API：按用户配置 base URL/path/token 的通用 POST 适配器。health 主要检查配置存在；不是 API 权限验证。未经官方文档与测试账号验证。
- RPA：没有实际页面驱动时返回未就绪；需要授权账号、允许自动化的确认、选择器与独立 Worker。
- 后端本地草稿：落 JSON 文件；不是多实例事务数据库。并发写、版本历史、远端失败补偿与审计仍需完善。

## 已识别的技术债与风险

- 旧 `crm.html` 和 `prototype-api.ts` 很大；需要按模块渐进拆分，不能一次重写全部 CRM。
- 前后端存在两套阶段实现，未来必须建立适配层及统一领域契约；不能把演示数据悄悄当真实业务数据。
- 旧 deliver 路由需审计外部调用前的审核校验、Mock 回执标识和任务完成语义；在这项审计完成前不得打开真实小满写权限。
- 当前预览人工完成只校验依据非空；不是核验第三方证明，管理视图也不是多人实时协作。
- 本地演示数据可被浏览器开发工具修改，不作为审计证据。
- 全球城市坐标是内置参考；尚未做真实客户地址标准化/地理编码/隐私授权。
- 历史文档中的“已验收”属于历史描述，不自动计入本次验证。
