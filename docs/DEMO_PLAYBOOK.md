# 企业工作台演练：没有 API 时如何展示

2026-09-12。实现入口 `/`；运行 `npm run preview:dev`，打开 http://127.0.0.1:5190/。

## 向企业说明

这是 CardBot 在接入企业数据和小满后预期的工作方式演练。所有客户、邮件、任务与小满回执均为虚构，程序只在当前浏览器运行。它可验证页面体验、任务状态和审核流程，不能证明已完成小满集成或真实 AI 理解。

## 七步演练

总览点击“播放演练”。每步约 7 秒，可暂停、继续、上一步、下一步、直接跳步、重播和退出。演练中的 08:00–17:35 是剧情时间，右上方上海时钟仍为真实时间。页面后台隐藏时暂停推进。

| 步骤 | 展示内容 | 要点 |
| --- | --- | --- |
| 08:00 早间 | Jojo 的邮件、经理安排、部门协作三项任务 | 同一人、同一批稳定 ID |
| 09:15 历史 | 两封询价往来和可点击引用 | 型号和数量明确，旧报价过期 |
| 09:20 草稿 | 根据预置模板生成回复 | 不编造价格、交期；未调用模型 |
| 09:25 审核 | 演示业务员批准后的状态 | 这是剧情模拟审批，不是真实员工审核证据 |
| 09:26 保存 | 模拟小满草稿箱、收件人/主题/正文和模拟回执 | SIM 前缀，未写入真实小满 |
| 17:30 晚间 | 汇总和地址完成，报价仍待跟进 | 保存草稿不等于报价已发送 |
| 17:35 经理 | 同一批任务显示 2/3 完成 | 与个人视图同源，不另编完成率 |

## 手动尝试

退出演练恢复之前的手动数据。Jojo 是主角；经理可以看汇总及身份台账；Mina、Leo 当前没有分配任务。所有身份均为前端演示选择，并非真正登录。

1. 今日工作中选择任务，填写完成依据，再确认完成。晚间视图展示剩余卡点。
2. 客户与邮件中点击 EMAIL-000 / EMAIL-001 引用，查看对应原文。
3. 草稿与审核中生成预置回复，编辑后勾选核对，再审核。
4. 选择保存本地或“保存到小满 · 模拟”。模拟保存结果在站内模拟草稿箱中展示。
5. 点击“演示保存失败”：显示超时提示，保留正文。重新保存可得到模拟回执。
6. 再次编辑正文，会撤销审核并清除旧模拟回执，需重新审核保存。

## 数据边界

- 手动状态保留原 `cardbot_preview_v1`，旧的任务完成依据与草稿不会被播放覆盖。
- 演练按步骤生成独立快照，退出或刷新不把演练结果写入手动状态。
- 模拟回执使用 `cardbot_simulated_receipt_v1`，只有正文与已保存草稿匹配时才恢复。
- Git 同步代码、文档和测试，不同步浏览器记录；当前不同电脑或浏览器仍不会共享业务状态。
- 本次没有新增资料导入、真实模型生成、邮件在线读取、定时主动推送、后端团队同步或小满网页自动化。

## 后续真实接入需要替换什么

复用工作台导航与页面，逐步用后端任务/证据/草稿数据替换浏览器样例。企业用户在服务端建立身份和权限；有正式邮件端点时接 API，否则在授权环境校准 RPA。真实验收必须包含小满草稿箱查询、字段比对和重新登录后的持久化复核。不要将 SIM 回执改个名字就当远端成功。
