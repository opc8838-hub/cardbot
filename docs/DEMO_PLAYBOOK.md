# 企业工作台演练：没有 API 时如何展示

2026-09-12。实现入口 `/`；运行 `npm run preview:dev`，打开 http://127.0.0.1:5190/。

## 向企业说明

这是 CardBot 在接入企业数据和小满后预期的工作方式演练。所有客户、邮件、任务与小满回执均为虚构，程序只在当前浏览器运行。它可验证页面体验、任务状态和审核流程，不能证明已完成小满集成或真实 AI 理解。

## 十步演练

总览点击“播放演练”。每步约 7 秒，可暂停、继续、上一步、下一步、直接跳步、重播和退出。演练中的 08:00–17:35 是剧情时间，右上方上海时钟仍为真实时间。页面后台隐藏时暂停推进。

| 步骤 | 展示内容 | 要点 |
| --- | --- | --- |
| 08:00 目标客户 | 定义产品、市场、客户类型与排除项 | 先说清楚什么企业值得找 |
| 08:06 企业发现 | 3 家候选企业与匹配分 | 先看匹配和业务信号，不先堆邮箱 |
| 08:12 背景判断 | 为什么匹配、为什么是现在、资料来源 | 形成可核对的开发判断 |
| 08:18 联系与切入 | 负责人、联系方式来源、合作切入点 | 开发信仍进入统一草稿审核 |
| 09:00 今日工作 | 开发跟进、客户邮件与内部协作汇总 | 两条业务线进入同一任务视图 |
| 09:15 历史邮件 | 两封询价往来和可点击引用 | 型号和数量明确，旧报价过期 |
| 09:20 回复判断 | 根据事实准备老客户回复 | 不编造价格、交期；未调用模型 |
| 09:25 统一审核 | 业务员批准后的状态 | 开发信与客户回复共用人审门槛 |
| 09:26 草稿记录 | 本地草稿、收件人/主题/正文和读回 | 未写入真实小满，未发送 |
| 17:35 团队汇总 | 同一批任务显示 2/3 完成 | 个人和经理看到相同依据与卡点 |

## 手动尝试

退出演练恢复之前的手动数据。Jojo 是主角；经理可以看汇总及身份台账；Mina、Leo 当前没有分配任务。所有身份均为前端演示选择，并非真正登录。

1. 今日工作中选择任务，填写完成依据，再确认完成。晚间视图展示剩余卡点。
2. 客户开发中从“开始寻找匹配企业”逐步前进，查看企业背景、开发判断、联系人来源与合作切入点。
3. 点击“进入统一草稿审核”，核对开发信依据并人工审核；保存后查看本地审计摘要。
4. 客户与邮件中点击 EMAIL-000 / EMAIL-001 引用，查看对应原文。

## 顶部屏保预览

顶部账号右侧的小播放图标用于立即预览大地球屏保，不会开始十步业务演练。讲解暂停时保持 20 秒不操作，页面也会自动进入屏保；屏保出现后可以继续移动鼠标查看，只有点击任意位置、触摸、滚动或按键才回到离开前的工作台位置。
5. 草稿与审核中切换“新客户开发信 / 现有客户回复”，验证两条业务线共用机制。
6. 现有客户回复可编辑；修改正文会撤销审核并清除旧模拟回执，需重新审核保存。

## 数据边界

- 手动状态保留原 `cardbot_preview_v1`，旧的任务完成依据与草稿不会被播放覆盖。
- 演练按步骤生成独立快照，退出或刷新不把演练结果写入手动状态。
- 模拟回执使用 `cardbot_simulated_receipt_v1`，只有正文与已保存草稿匹配时才恢复。
- Git 同步代码、文档和测试，不同步浏览器记录；当前不同电脑或浏览器仍不会共享业务状态。
- 本次没有新增资料导入、真实模型生成、邮件在线读取、定时主动推送、后端团队同步或小满网页自动化。

## 后续真实接入需要替换什么

复用工作台导航与页面，逐步用后端任务/证据/草稿数据替换浏览器样例。企业用户在服务端建立身份和权限；有正式邮件端点时接 API，否则在授权环境校准 RPA。真实验收必须包含小满草稿箱查询、字段比对和重新登录后的持久化复核。不要将 SIM 回执改个名字就当远端成功。
