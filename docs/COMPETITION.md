# 比赛要求与验收映射

## 来源与适用性

依据用户提供的“望京企业命题参赛需求文档（AI 销售助手 + AI 工作助手）”整理。该文本自述整理自《望京企业命题参赛指南 - 含小满网页版与接入说明.pptx》，不是最终官方赛规。此仓库保存可执行的要求摘要，未把用户私有原始材料或登录资料公开上传。

**参赛资格、截止时间、评分权重、提交格式、部署限制、开源与授权条款尚未拿到最终文件，必须向主办方确认，不能猜。**

## 合并赛题的产品定位

CardBot 不是重做一套小满 CRM，而是站在现有 CRM 前的一层工作助手：从同一批业务信息形成任务，查阅历史沟通与事实，拟写安全草稿，交给人审核，再写入小满草稿箱。早间知道要做什么，晚间知道为什么还没完成。

用户确定的优先顺序：工作助手同批任务 → 历史邮件/事实/审核/本地草稿 → 统一小满连接器 → 真实小满验证 → 现有智能获客整合。不要先做所有外贸 SaaS 模块。

## 销售助手硬要求

1. 现有客户：本次来信 + 全部获授权历史往来 + 产品资料；识别诉求，分清确认事实和待核实事项。
2. 每项事实需能回查来源：原邮件 ID、原文引述、时间、客户/事项关联，不是只有模型总结。
3. 价格、交期、赔偿承诺必须有确认资料并经人工审核。资料不足不能擅自补全。
4. 邮件收件人、主题、正文及关联客户完整保存到小满草稿箱。AI 不直接发送。
5. 验收证据是“小满内可查”：打开草稿箱可找到，重新登录后仍存在，内容一致。
6. 保存失败必须保留本地内容，显示失败原因及下一步，不允许丢稿或假报成功。
7. 新客户阶段需展示客户名称、网站、邮箱、来源、合作切口和完整草稿；找不到邮箱就提示缺失，不能造联系信息。

本项目增加一道小满保存前人工审核，不替代小满内最终审核发送环节。

## 工作助手硬要求

- 来源包含客户邮件、上级安排、跨部门协同；合并同一事件的重复消息。
- 字段包括任务 ID、名称、客户/事项、原始来源、处理人、期限、状态、完成依据。
- 没有明确期限就标记“待确认”，不猜截止时间。
- 早间清单与晚间复盘必须是同一批任务，不允许换一套演示数据。
- 个人端和管理端共用状态；管理者能按人汇总并找到停滞原因。
- 阅读不等于完成；有草稿不等于已发送报价。状态判断方式应写明人工确认或系统证据。
- 未完成提醒应包含任务名、缺失条件、下一步行动，而不只是“您有 N 条待办”。

## 对应现有实现与缺口

| 验收项 | 已有基础 | 剩余工作 |
| --- | --- | --- |
| 同批全天任务 | 后端 workday + 新 UI 本地演示 | UI 接真实接口、多人/定时触发验收 |
| 原始来源/完成依据 | 字段、预览源文、任务状态检查 | 真实数据来源跳转、证据真实性、去重验收 |
| 历史邮件事实 | EML 解析 + 草稿 facts 模型 | 批量邮箱连接、附件、历史冲突与最新版本判断 |
| 安全草稿 | 人工审核门槛；预览安全模板 | DeepSeek 结构化输出、事实校验、提示注入防护 |
| 小满保存 | 连接器三模式接口骨架 | 官方协议或 RPA 驱动、读回比对、重登录证据 |
| 保存失败不丢稿 | 本地草稿基础 | 幂等、重试、远端不确定状态、重复稿防护 |
| 新客户开发 | 旧获客模块保留 | 来源合法授权/联系方式核验/串联小满草稿 |

## 可复现的本阶段演示（约 4 分钟）

1. 说明这是 Mock/本地阶段，不是真实小满。进入新工作台，展示 3 条固定任务 ID。
2. 早间查看报价任务，展示客户原文、200 件 CB-20、价格/交期待确认。
3. 打开汇总任务，输入“REPORT-001 已提交汇总（演示）”并人工确认完成。
4. 生成报价回复草稿，展示没有价格/交期承诺；未审核时保存按钮不可用。
5. 核对后审核、保存；展示 LOCAL ONLY 提示，刷新后找回。修改正文后重新要求审核。
6. 回到晚间复盘，展示相同任务 ID，汇总已完成，报价和地址仍待确认，提醒带行动。
7. Team 汇总与个人清单一致。Connect 说明下一步需要主办方提供哪些接口/账号。

## 最终赛前必须另补的验收证据

测试账号/授权范围记录（不含密码）→ 一封脱敏历史邮件及证据 → 审核日志 → 小满草稿 ID → 草稿箱截图 → 内容逐字段比对 → 退出并重新登录 → 再次截图和比对。记录时间、版本 commit、操作者、结果；失败也要保留记录。仅凭 HTTP 200 或 Mock ID 不通过。

异常用例至少覆盖：缺邮箱、缺历史约定、报价与交期冲突、凭证过期、限流/超时、保存失败、重复点击保存、重新登录失效、修改已审核稿、未审核请求远端写入。
