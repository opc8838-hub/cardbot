# CardBot 前端设计规范（全球贸易工作台方向）

> 已被根目录 FRONTEND_DESIGN_SPEC.md v2 替代，仅保留历史讨论。特别是登录页布局、动画时长、地球构成不可再按本文件实施。

状态：设计基线，暂不实施  
版本：1.0  
日期：2026-09-12

## 1. Design Read

这是一个面向全球贸易团队的 AI 工作助手：品牌入口可以大胆、实验、国际化；进入系统后必须冷静、清晰、可信。视觉语言采用瑞士式网格、超大英文排版与细小实时数据的强反差。参考 Ansyn 的节奏和信息组织，不复制其版式、文案、地球资产或动画实现。

设计强度：

- 品牌入口：DESIGN_VARIANCE 9 / MOTION_INTENSITY 8 / VISUAL_DENSITY 5
- 工作台：DESIGN_VARIANCE 6 / MOTION_INTENSITY 4 / VISUAL_DENSITY 7

一句话方向：**The workday for global trade. Evidence in. Reviewed drafts out.**

## 2. 设计边界

### 要做

1. 用多语言问候说明 CardBot 服务全球贸易，而不只是做装饰动画。
2. 用英文大字呈现已经存在的产品能力，并用真实字段作为小字背景。
3. 将全球地球作为工作台的环境层和数据导航层，而不是抢占工作的主角。
4. 保留现有登录、全天工作、获客、客户、商机、草稿、审核和连接器流程。

### 不做

1. 不直接复制 Ansyn 的地球、页面比例、城市列表、句子或素材。
2. 不使用随机乱码伪装“科技感”；所有可读字段必须来自 CardBot 的真实业务语言。
3. 不把尚未真实验证的小满能力写成“已接入”。测试完成前统一写为 `Connector ready` 或 `Mock / API / Browser modes`。
4. 不让营销动效进入高频操作页面；工作台首先保证可读性和效率。
5. 不使用玻璃拟态、大面积渐变、发光紫色、漂浮圆球、胶囊堆叠或大量阴影。

## 3. 总体体验结构

整个体验由三个连续阶段组成，但产品只保持一套主视觉主题。

### A. Multilingual Greeting / 多语言开场

- 仅出现在首次进入登录入口时，不在系统内部切页时重复。
- 全屏近黑色背景，中心只有一个问候词和极少量 CardBot 标识。
- 词序建议：`Hello → 你好 → Hola → Bonjour → مرحباً → Olá → こんにちは`。
- 采用“垂直滚轮 / 遮罩替换”运动，不做打字机动画。
- 单词切换约 320–420ms，总时长控制在 2.8–3.4 秒。
- 最后一句落到：`Trade has no single language.`，随后用整页遮罩揭开浅色主页面。
- 右上角提供低干扰的 `Skip intro`；`Esc`、`Enter`、点击也可跳过。
- 同一浏览器会话只播放一次。退出登录后重新登录也不强制重播。
- `prefers-reduced-motion: reduce` 时不滚动，只显示 `Hello / 你好` 和最终句，400ms 内进入下一阶段。
- 阿拉伯语必须使用正确 RTL 方向；不同语言不使用国旗图标代表。

说明：黑色仅是短暂的启动遮罩，不是页面中的一个“深色主题区”。遮罩结束后，登录、功能介绍与系统工作台统一使用浅色纸张主题。

### B. Capability Manifesto / 英文能力宣言

这一阶段承担“CardBot 到底做什么”的说明，不做空泛品牌口号。

主排版词：

| 大字 | 对应已有能力 | 可用小字证据 |
|---|---|---|
| `WORKDAY` | 同一批任务贯穿早晚 | `workday_date` `owner` `checkpoint` `task_status` |
| `EVIDENCE` | 历史邮件与事实依据 | `message_id` `source_ref` `evidence_count` `observed_at` |
| `REVIEW` | 人工审核与权限边界 | `reviewer` `decision` `reviewed_at` `risk_level` |
| `DRAFT` | 本地邮件 / 小满草稿 | `subject` `recipient` `draft_status` `connector_mode` |
| `DELIVER` | Mock、API、Browser 三种连接方式 | `mock` `official_api` `playwright_rpa` `last_sync` |

推荐主标题：

> ONE WORKDAY.  
> EVERY FACT.  
> REVIEWED BEFORE ACTION.

推荐说明：

> CardBot turns customer history into cited facts, reviewable work, and safe local drafts — across markets, time zones, and systems.

排版规则：

- 12 栏网格，不平均分配大字；让词跨栏、错位、局部被屏幕裁切，形成编辑感。
- 大字使用无衬线粗体，小字使用等宽字体。
- 蓝色只强调一个当前动作，例如 `REVIEW` 或 `DELIVER`，同屏不出现多个竞争色。
- 背景数据文本必须可解释；悬停或键盘聚焦时可显示字段含义。
- 不加入无作用的“向下滚动”提示。入口动作使用 `Enter CardBot` 和 `View the workflow`。
- 未登录用户看到的是能力说明与登录入口；已登录用户可直接跳过本阶段进入工作台。

### C. Global Workbench / 全球实时工作台

地球是工作台背景和数据导航器，不是单独的装饰页面。

- 默认缓慢自转；推荐完整一圈 100–140 秒。
- 用户拖动、滚轮缩放、点击国家或选择客户地址时立即暂停。
- 交互结束 4.5–6 秒后恢复自转；锁定某客户或市场时不强制恢复。
- 页面隐藏、组件离开视口、设备省电或减少动效时停止渲染。
- 点击客户、国家、市场或任务，地球以 600–800ms 转到目标区域。
- 不自动循环跳转客户地址，避免工作台自己乱动。自动变化只允许地球缓慢自转和时间字段更新。

## 4. 差异化地球设计

不使用参考图中的灰色行政区填充地球。CardBot 的地球应由“业务数据语言”构成。

### 视觉构成

1. 球体轮廓：细灰色经纬线与极淡国界，只提供空间方向。
2. 数据表面：沿球面排布真实字段片段，例如：
   - `evidence:12`
   - `draft:review`
   - `market:DE`
   - `timezone:UTC+01`
   - `connector:mock`
   - `last_sync:14:32`
3. 活跃点：仅用 CardBot 蓝表示有真实客户、任务或信号的位置。
4. 路径线：只有存在业务关系、邮件、任务或贸易记录时才显示；不画虚假的“全球连线”。
5. 数据状态无法核验时显示 `UNVERIFIED`，不制造经纬度、城市或关系。

### 地址定位规则

- 地址定位顺序：已确认经纬度 → 已确认城市 → 已确认国家 → 不定位。
- 同一标准化地址只保留一个地图点，点内聚合客户数、任务数和草稿数，避免重叠闪烁。
- 同名地址但国家不同不能合并。
- 地址只到国家级时，界面必须标记 `country-level location`，不能伪装成精确城市坐标。
- 客户地址改变后才重新定位；不能每秒重新地理编码。
- 外部地理编码服务如后续引入，必须有缓存、限流、来源记录和人工修正入口。

## 5. 实时信息字段

右上角或地球旁的信息面板保持极简，使用等宽数字和固定宽度，更新时间时不跳版。

| 字段 | 示例 | 更新频率 | 来源 |
|---|---|---:|---|
| `LOCAL TIME` | `14:32:08` | 1 秒 | 浏览器时钟 + IANA 时区 |
| `TIME ZONE` | `Europe/Berlin · UTC+02:00` | 地点变化时 | 已确认地址 / 国家映射 |
| `LAT / LON` | `52.5200 N / 13.4050 E` | 地点变化时 | 已确认坐标 |
| `MARKET` | `Germany · DE` | 选择变化时 | 客户 / 市场数据 |
| `OPEN TASKS` | `12` | 收到任务事件时 | CardBot 工作任务接口 |
| `EVIDENCE` | `38 records` | 收到证据事件时 | CardBot 证据接口 |
| `DRAFT STATUS` | `Awaiting review` | 草稿状态变化时 | 草稿工作流 |
| `CONNECTOR` | `Mock / API / Browser` | 连接模式变化时 | 小满连接器状态 |
| `LAST SYNC` | `14:31:42` | 同步完成时 | 连接器事件 |

实时不等于不停请求：时间在前端每秒刷新；业务字段通过现有事件或正常轮询刷新。网络失败时保留最后值，并明确显示 `Last updated`，不能把旧数据伪装成实时数据。

## 6. 视觉系统

### 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--ink` | `#101112` | 主文字、开场背景 |
| `--paper` | `#F6F7F4` | 登录与工作台主背景 |
| `--surface` | `#FFFFFF` | 需要遮挡地球的工作区 |
| `--muted` | `#737773` | 次要说明 |
| `--line` | `#D8DCD7` | 网格、分隔线、表格边线 |
| `--signal` | `#2F5BFF` | 唯一品牌强调色、活跃位置 |
| `--danger` | `#C83A32` | 错误和高风险动作，仅语义使用 |
| `--success` | `#147A56` | 已核验、已完成，仅语义使用 |

禁止渐变作为主视觉；不使用发光阴影。层级主要靠字号、留白、线条与黑白反差完成。

### 字体

- 英文主字体：`Geist Sans`（自托管）或系统回退 `Arial / Helvetica Neue / sans-serif`。
- 中文字体：`Noto Sans SC / PingFang SC / Microsoft YaHei / sans-serif`。
- 数据字体：`IBM Plex Mono`（自托管）或 `ui-monospace / Consolas / monospace`。
- 不依赖用户电脑可能不存在的商业字体。
- 数字使用 `font-variant-numeric: tabular-nums`。

### 字号与网格

- 桌面大字：`clamp(72px, 12vw, 184px)`，行高 0.84–0.95。
- 开场问候：`clamp(56px, 8vw, 124px)`。
- 正文：15–18px，行高 1.5–1.7。
- 数据字：10–13px，行高 1.35–1.5。
- 桌面使用 12 栏，外边距 32–64px；平板 8 栏；手机 4 栏，外边距 18–20px。
- 页面最小高度使用 `100dvh`，避免手机浏览器地址栏造成跳动。

### 形状

- 卡片圆角 0–6px，默认 2px；表格、面板优先直角。
- 按钮圆角 2–4px；不把按钮和标签都做成胶囊。
- 面板默认无阴影，用 1px 分隔线和不超过 4% 的底色差建立层级。

## 7. 工作台可读性规则

1. 地球常态透明度为 5%–10%；进入地图交互模式才提高到 18%–28%。
2. 文字和表格所在区域必须有实色或局部遮罩，正文对比度至少达到 WCAG AA。
3. 地球不得穿过输入框、审核按钮、表格正文和弹窗。
4. 工作台不使用超大英文词；大字只属于登录前的品牌表达。
5. 工作任务、证据、审核和草稿是第一视觉层；地球是第三视觉层。
6. 当前用户、当前日期、连接器模式和数据新鲜度必须始终可见。

## 8. 动效规范

- 进入动画使用 `opacity + transform + clip-path`，不使用改变布局的动画。
- 普通交互 120–220ms；页面揭示 500–800ms；地球定位 600–800ms。
- 缓动推荐 `cubic-bezier(.16, 1, .3, 1)`，旋转使用线性。
- 不监听每一帧滚动位置驱动布局；进入视口使用 IntersectionObserver 或 CSS scroll-driven animation。
- 不劫持滚动，不强制整屏吸附，不播放自动音频。
- 所有无限动画都必须在不可见时暂停。
- `prefers-reduced-motion` 下禁用问候滚轮、文字漂移、地球自转和路径流光，仅保留即时状态切换。

## 9. 响应式规则

### ≥ 1280px

- 功能宣言可使用强烈的跨栏错位排版。
- 地球占工作台宽度的 48%–62%，从右侧或中央偏后露出。
- 实时字段分布在角落，但保持同一阅读轴。

### 768–1279px

- 保留大字，但减少跨栏和裁切。
- 地球居中靠后，信息面板收敛到 2 列。

### < 768px

- 问候动画仍居中，最多显示 5 种语言，总时长不增加。
- 英文大字按语义分行，不让字母水平溢出。
- 工作台地球变成可展开的“全球视图”区域，不持续铺在表单后方。
- 所有主要操作触控高度不低于 44px。
- RTL、中文、日文和英文都要做断行测试。

## 10. 组件边界

建议新增或重构为以下独立组件，避免继续把所有视觉和行为塞进一个 HTML 文件：

- `IntroGreeting`：多语言开场、跳过、会话记忆、减少动效。
- `CapabilityManifesto`：英文能力大字与真实字段层。
- `TradeDataTexture`：把业务字段排成可控的数据纹理。
- `GlobalWorkbenchGlobe`：复用现有 Globe.gl 能力，承载自转、定位、暂停和销毁。
- `RealtimeLocationPanel`：时间、时区、经纬度、市场和同步状态。
- `WorkbenchBackdrop`：控制地球与实际页面之间的遮罩和层级。

现有 `customer-map.ts` 已具备自转、国家聚合、点击定位、交互暂停、页面隐藏停转与减少动效处理，应优先复用并抽象，不重新引入另一套 3D 地球库。

## 11. 性能与降级

- 开场不能等待地球代码加载；地球和世界地图数据在问候动画后异步加载。
- 世界地图数据单独分包，只有进入需要地球的页面才加载。
- 目标：登录入口 LCP ≤ 2.5 秒，交互响应 INP ≤ 200ms，布局偏移 CLS ≤ 0.1。
- 中低端设备降低球面文字数量和点数量，不降低业务数据准确性。
- WebGL 不可用时显示 2D 投影地图或静态数据网格；登录、任务和审核必须照常可用。
- 同一地理点优先聚合，避免渲染数千个重叠对象。

## 12. 无障碍与可信度

- 所有动画提供跳过方式；键盘焦点清晰可见。
- 问候词变化区域使用克制的 `aria-live`，避免读屏连续播报七次；读屏默认只读最终含义。
- 颜色不是唯一状态依据，状态同时显示文字或图标。
- 关闭动画、WebGL 失败、网络断开时，核心工作流仍可使用。
- 地址、坐标、来源、证据和同步时间必须可追溯；未知数据明确显示未知。

## 13. 建议实施顺序

1. **设计令牌与独立预览**：先实现字体、颜色、网格和 `IntroGreeting`，不碰业务页面。
2. **英文能力宣言**：把已有能力映射为 `WORKDAY / EVIDENCE / REVIEW / DRAFT / DELIVER`，接真实字段但不写假数据。
3. **地球视觉重构**：复用现有 Globe.gl，增加数据文字纹理、时区面板和地址聚合规则。
4. **工作台融合**：逐页确认背景遮罩、表格可读性和地图交互边界。
5. **验证**：桌面、手机、RTL、减少动效、WebGL 降级、慢网和断网测试。

## 14. 验收标准

- 首次进入能看到 `Hello → 你好 → 多语言`，3.4 秒内完成，可跳过且同会话不重复。
- 功能页只宣传真实存在或明确标注为“准备就绪”的能力。
- 地球外观与参考站有明显差异，并能看出由 CardBot 数据字段构成。
- 地球能自转、拖动、暂停、恢复、按已确认地区定位。
- 同一标准化地址不会生成多个重叠点。
- 时间每秒正确更新；时区、经纬度和业务字段有明确来源与更新时间。
- 在减少动效和 WebGL 不可用时，核心登录与工作流完全可用。
- 现有登录、全天工作、证据、审核、草稿、客户和连接器流程不被破坏。
